# wrtcast

**Пульт для Chromecast, который живёт на роутере с OpenWrt.**

Открываете страницу в браузере телефона, ищете фильм или сериал, нажимаете на
серию, и она запускается на телевизоре. Не нужно ставить приложение, не нужен
Google Home, а телефону не надо оставаться включённым во время просмотра. Всю
работу делает роутер: он общается с Chromecast по протоколу Cast, получает
ссылки на потоки и раздаёт видео.

```
 браузер телефона                  роутер с OpenWrt                      Chromecast
┌─────────────┐   HTTP    ┌──────────────────────────────┐  Cast v2   ┌────────────┐
│  веб-UI     │──────────▶│ uhttpd :8088                 │──(TLS)────▶│  Default   │
│ (один HTML- │           │  ├─ index.html               │   :8009    │  Media     │
│  файл)      │◀──────────│  └─ /api → wrtcast (ucode)   │            │  Receiver  │
└─────────────┘   JSON    │        ├─ castctl  (C) ──────┼────────────┘     │
                          │        └─ /api/p медиапрокси │◀─────────────────┘
                          └──────────────┬───────────────┘   HLS-плейлисты
                                         │ HTTP/JSON          и сегменты
                                         ▼
                                  ┌─────────────┐
                                  │  title-api  │  поиск, описание, потоки
                                  │  (Go)       │  (где угодно: в LAN, на VPS)
                                  └─────────────┘
```

## Из чего состоит

В репозитории три независимых приложения, каждое собирается и работает само
по себе.

| | Что это | Где работает | Размер |
|---|---|---|---|
| [`castctl/`](castctl/) | Консольный контроллер Chromecast, написанный с нуля на C: Cast v2 поверх TLS (mbedtls), самописные protobuf и JSON, поиск устройств через mDNS. Без состояния: одна команда на запуск, демон не нужен. | роутер (или любая Unix-система) | бинарник ~37 КБ для aarch64 |
| [`router-app/`](router-app/) | `wrtcast` — CGI-скрипт на ucode, который связывает всё вместе, плюс мобильный веб-интерфейс в одном файле. Использует только пакеты, которые уже есть в OpenWrt. | роутер | скрипт ~16 КБ, UI ~12 КБ в gzip |
| [`title-api/`](title-api/) | Сервис на Go с gRPC и HTTP/JSON-шлюзом: поиск тайтлов, подробности (описание, рейтинги, сезоны и серии) и получение HLS-потоков. | где угодно, лишь бы роутер до него доставал | Docker-образ ~24 МБ |

## Возможности

- **Поиск и карточки** из любого браузера на телефоне: постеры, описание,
  рейтинги Кинопоиска и IMDb, сезоны и серии.
- **Полноценный пульт:** пауза и продолжение, перемотка, ±10 с, громкость и
  выключение звука, выбор озвучки и субтитров с понятными названиями,
  предыдущая и следующая серия с переходом между сезонами.
- **Несколько телевизоров:** Chromecast находятся через mDNS, в интерфейсе есть
  выбор устройства, который запоминается.
- **Медиапрокси:** HLS-плейлисты, сегменты и постеры можно пропускать через
  роутер. Так в одном месте задаются User-Agent, дополнительные заголовки и
  CORS, которые часто нужны подписанным ссылкам CDN и капризным ресиверам.
- **Надёжный `play`:** castctl ждёт, пока ресивер действительно начнёт
  воспроизведение, и сообщает об ошибке при `LOAD_FAILED` или остановке с
  причиной, а не верит первому, часто преждевременному ответу.
- **Минимум ресурсов:** на роутер не нужно ставить ничего, кроме бинарника
  castctl. Запрос статуса занимает ~0,2 с, запуск фильма вместе с получением
  потока — ~3–9 с.

## Требования

- **Роутер:** OpenWrt 24.10 или похожий, с пакетами `ucode`, `ucode-mod-fs`,
  `ucode-mod-uci`, `uhttpd` и `uclient-fetch` (все есть в стандартной прошивке)
  и `libmbedtls` для castctl. Проверено на роутере с aarch64.
- **Телевизор:** любой Chromecast или телевизор с поддержкой Cast, на котором
  запускается Default Media Receiver.
- **title-api:** Go 1.26 или Docker на любой машине, до которой роутер может
  достучаться по HTTP.

## Быстрый старт

**1. Запустите title-api** там, где его увидит роутер:

```sh
cd title-api
make && HTTP_ADDR=:8080 ./title-api
# или: docker build -t title-api . && docker run -p 8080:8080 title-api
```

В [`title-api/compose.yaml`](title-api/compose.yaml) есть вариант для VPS:
API доступен только через WireGuard, а исходящие запросы идут через домашний
роутер.

**2. Соберите castctl и скопируйте на роутер.** Скрипт собирает его под
aarch64/musl в контейнере Alpine:

```sh
castctl/scripts/build-aarch64.sh
scp castctl/build/castctl-aarch64 root@192.168.1.1:/usr/bin/castctl
```

Для других архитектур есть пакет для OpenWrt SDK:
[`castctl/openwrt/`](castctl/openwrt/castctl/Makefile).

**3. Разверните бэкенд и интерфейс:**

```sh
ROUTER=root@192.168.1.1 router-app/scripts/deploy.sh
ssh root@192.168.1.1 "uci set wrtcast.main.api_url='http://<адрес title-api>:8080' && uci commit wrtcast"
```

Скрипт создаёт отдельный экземпляр uhttpd на порту 8088, LuCI он не трогает.

**4. Откройте на телефоне `http://192.168.1.1:8088/`.**

Настройки, HTTP API и прокси описаны в [`router-app/README.md`](router-app/README.md),
эндпоинты title-api — в [`title-api/README.md`](title-api/README.md).

## castctl отдельно

castctl полезен и без остального проекта, например в shell-скриптах или в
интеграции `command_line` для Home Assistant:

```sh
castctl discover                                     # [{"name":"Living Room TV","host":"192.168.1.50",...}]
castctl -H "Living Room TV" play https://example.com/stream.m3u8
castctl -H 192.168.1.50 status                       # JSON: приложение, громкость, состояние, дорожки
castctl -H 192.168.1.50 pause | resume | stop | quit
castctl -H 192.168.1.50 seek 600 | ff 30 | rew 10   # секунды
castctl -H 192.168.1.50 audio en | subs off          # id дорожки, язык или название
castctl -H 192.168.1.50 volume 40 | mute | unmute
```

`-H` принимает адрес, имя устройства или его id. Каждая команда печатает одну
строку JSON и при ошибке завершается с ненулевым кодом. Собрать на своей
машине: `make` (на macOS — `make MBEDTLS=$(brew --prefix mbedtls@3)`).

## Безопасность

- У веб-интерфейса и API по умолчанию нет авторизации. Держите порт 8088
  внутри LAN или задайте `option token` в `/etc/config/wrtcast`.
- Медиапрокси ходит только на публичные `http(s)`-хосты и в настроенный
  title-api, поэтому через него нельзя попасть в локальную сеть.
- У title-api авторизации тоже нет. Не выставляйте его в интернет: готовый
  compose-файл привязывает его только к адресу WireGuard.

## Отказ от ответственности

wrtcast — это пульт и ретранслятор потоков. Он не хранит и не распространяет
никакой контент. title-api — пример резолвера для стороннего сайта; вы сами
отвечаете за то, что у вас есть право смотреть то, что вы с его помощью
запускаете.
