# Ревью репозитория — ноябрь 2026

Полный проход по всем компонентам (router-app, www, title-api, castctl, faces, music, CI), 2026-11-21.
Строки указаны на момент ревью — при работе сверять по имени функции.

## Вердикт

Большой рефакторинг/переписывание **не нужен**. Код лучше, чем ожидалось: плотные комментарии «почему»,
мёртвых функций почти нет, Go покрыт тестами (provider ~77 %, telemetry/playback_session/alternative_player 92–96 %,
tmdb 83 %, music 81 %, faces 75 %, grpcserver 56 %, marking 52 %), `go vet` и `go test -race` чистые, castctl собирается
под `-Wall -Wextra` без предупреждений, модели в faces/music грузятся один раз.

Долг: копипаста мелких хелперов, отсутствие кеша на скрапинге провайдера, пачка мелких багов. Модульный распил
`wrtcast.uc` / `index.html` / `provider` — не нужен (см. «Не трогать»).

## Волна 1 — title-api (под тестами, самая большая польза)

1. **Кеш `TitleMetadata` + общий цикл embed'ов.** `provider/metadata.go:46` не кеширует; «страница фильма → цикл по
   embed'ам» скопирован 5 раз (`client.go` Streams, `series.go` fetchSeries/EpisodeStreams, `marks.go` EpisodeToMark,
   `metadata.go` mediaTypeFromEmbeds). Открытие тайтла + Play качает одни страницы провайдера 2–3 раза (TMDB reverse
   матчинг дёргает `TitleMetadata` ещё раз на кандидата). Решение: generic TTL+singleflight из `series_cache.go`
   на `TitleMetadata` (несколько минут, ошибки не кешировать); `c.embedPages(...)`. Embed HTML **не** кешировать
   надолго — там подписанные HLS-ссылки.
2. **TMDB.** `tmdb/client.go:144 search` не идёт через `cached()`: `quick` и фоновый `match` повторяют одни и те же
   до 4 поисков; с `askClaude=false` результат `errUnsettled` не сохраняется → неоднозначный тайтл стоит до 8 запросов
   на каждое открытие. Решение: `cached("search:<kind>:<query>", ~1 ч)` + поиски параллельно с сохранением порядка
   слияния. `grpcserver/server.go:191-206 GetTitleDetails`: `client.Series` и `tmdb.Opened` — в errgroup.
3. **Утечки/локи.** `c.videos` (`alternative_player.go:689`, sync.Map) никогда не чистится — хранить Video на
   `alternativeSource`. `masterStore.entry` (`master_store.go:86`) сканирует до 4096 записей под глобальным мьютексом
   на каждый медиа-запрос — проверять срок только у искомой, периодическая чистка.
4. **HLS-парсеры, ~8 штук** (`playlist.go`, `align.go`, `alternative_media.go`, `audio_ahead.go`,
   `alternative_parts.go`), расходятся: часть с дефолтным 64 КБ лимитом bufio без `scanner.Err` (длинная строка молча
   обрывает разбор), два резолвера URL, два парсера атрибутов. `marks.go:134 VideoSegments` == `align.go:697
   primaryVideo.load`. Решение: пакет `provider/hls` (ParseMaster/ParseMedia), сначала golden-тесты на текущий вывод.
5. **Копипаста хелперов.** Атомарная запись в 3 вариантах (`tmdb/images.go:144`, `music/service.go:127`,
   `faces/files.go:38` — у двух фиксированный `.part`, гонка при параллельной записи); KV настроек
   (`marking/store.go:49-68` == `tmdb/store.go:53-72`); проверка ошибок аккаунта Claude + backoff
   (`tmdb/service.go:268-293`, `marking/service.go:293-310`); прямой транспорт без прокси ×5; самописный singleflight
   (`tmdb/cache.go:61`, `tmdb/images.go:104`) → `x/sync/singleflight`; «обновить сессию и повторить» ×3
   (`client.go:144`, `search.go:40`, `poster.go:35`), `get`/`postForm` почти одинаковые. Имена таблиц сохранить.
6. Мелочи структуры: медиа-хендлеры из `cmd/title-api/main.go` в `media.go`; `grpcserver/server.go` разрезать на
   файлы (60 % — маппинг в proto); `make proto` / buf.gen.yaml (генерация воспроизводится байт-в-байт, но нигде не описана).
7. NICE-TO-HAVE: generic LIFO-очередь вместо 4 копий (tmdb match, reverse, faces, marking); Chrome-клиент
   (`browser.go`, `chrome.go`, `websocket.go`) в `provider/chrome`; тесты на `internal/marker` (0 %), align/align_ahead
   (17–30 %), faces/music HTTP-хендлеры.

## Волна 2 — castctl и прокси

- `castctl.c:501 check_reply_type`: `char type[48]` читается неинициализированным, если в ответе нет `"type"` → `= ""`.
- `castctl.c:689-713 print_status`: app_id/state/idleReason/track type/lang печатаются без `jescape` — кавычка от
  устройства ломает JSON → роутер 502.
- `castctl.c:1316/1336/1367`: запись в `subs` до проверки `calloc` на NULL. `die()` без `noreturn`.
- `castctl.c:256`: нет таймаута на connect — выключенный ТВ подвешивает CGI (у `run()` в `wrtcast.uc:382` таймаута тоже нет).
- **Фильтр LAN в `/api/p` обходится** (`wrtcast.uc:1701-1712 proxy_target`): hex/octal IPv4 (`0xc0.0xa8.1.1`),
  хосты, резолвящиеся в приватные адреса (`*.nip.io`), не закрыта 100.64/10. Ограничено `rfc1918_filter` uhttpd.

## Баги

- `start()` отмечает прошлую серию просмотренной до castctl (`next_episode` 2738); упавший Play её не откатывает.
- Роутер и title-api выбирают «следующую серию» по-разному: `episode_after` (1438) идёт по порядку API, `nextEpisode`
  (`series.go:367`) сортирует и пропускает заблокированные сезоны. Лучше отдавать `next` из title-api.
- `series.go:254-266 EpisodeStreams`: сериал только на альтернативных плеерах с `ErrEpisodeNotFound` → `ErrNotSeries`.
- `align.go:627-644` (вероятно): после reload посреди цикла `range video.segments` идёт по старому срезу.
- `master_store.go:55/69`: TTL 6 ч от создания, а не от использования → пауза > 6 ч = 404 на мастер.
- `challenge.go:465`: ошибки `postForm` не `*statusError` — Search не отличает 403.
- `browser.go:648`: кешируемый ресурс > 8 МБ обрезается (сейчас безвредно).
- `main.go:128-129`: `TITLE_API_SEGMENTS_MB=2g` → Limit 0 → кеш сегментов молча выключен; так же `TITLE_API_AHEAD`.
- `main.go:571`: CORS без POST (скрыто, т.к. роутер проксирует server-side).
- `tmdb_cache` не чистится от старых версий ключей; 404 TMDB не кешируется.
- `musicSink` (`music.go:207`) буферизует 64 сегмента целиком — сотни МБ при медленном music.
- `/play` может превысить 60 с таймаут uhttpd (ретрай `api()` 2×20 с + повтор в `prepare` + castctl 20 с).
- Страница: несколько `prompt()` токена подряд при старте (1025-1028); старый ответ `/progress` затирает новый;
  двойной `/progress` при ошибке отметки (2629-2630); `tmdbs[k] ??=` перефетчит null (2741); мёртвая ветка `f.tmdb`
  в `markUpTo` (2836); «Вы смотрели» на странице человека не обновляется после отметок (2959).
- faces/music: нечисловой Content-Length → необработанный ValueError, соединение рвётся без ответа.

## Не трогать

- Эмуляция Chrome и телеметрии плеера (`telemetry.go`, `browser.go` заголовки, `playback_session.go`, `ads.go`,
  `requestAlternativePlayback`) — побайтный порядок заголовков/полей/таймингов, это защита от бана. Не объединять
  XHR-билдеры. Допустимо только косметически разрезать `telemetry.go` на файлы.
- Тайминги под реальный ТВ: autoskip/autonext (`plan`/`wake`/`ended`/`at_credits`), `volume_back`, тёплый старт
  `.w`, обновление CDN-заголовков, fd-3 трюк в `api()`, миграции в `init()`, ручные `urlenc`/`extinf`, ORDER BY в `cache_put`.
- Страница: жесты плеера (1110–1348), роутинг оверлеев `backs`/`afterBack` (1354–1464), Media Session и тихий луп,
  seek preview, `placeTips`.
- `relay()` в title-api, дизайн кеша TMDB, sectionlab (живой dev-тул), ручной protobuf/JSON в castctl,
  общий HTTP-бойлерплейт faces/music.

## UI (index.html) — баг-хант

Headless Chrome + мок `/api`, 390/320/1280/ландшафт. Строки — на момент ревью.

**Исправлено (2026-11-21):**
- Верхний градиент отъезжал при оттягивании страницы вверх: iOS rubber-band двигает всё содержимое скроллера,
  sticky `.lhead` (фон — только градиент `::after`) и бэкдроп тайтла ехали вниз, сверху открывалась голая полоса.
  `overscroll-behavior-y:none` на `#det,#list,#cast,#person` и на `:root`, пока они открыты (как уже было для `#pl.open`).
  На iPhone не проверено — headless не умеет rubber-band.
- Тёмные логотипы на тёмном фоне: `logoDark()` меряет логотип на канвасе после preload (он same-origin через
  `/api/p`), если ≥30 % видимых пикселей темнее L 0.07 — `#dlogo.dark` со светлым свечением. Кеш по URL в Map +
  `localStorage.logoDark`. Порог подобран на синтетике.

**Средние:**
1. `openNow` (~4725) при открытой странице человека/каста меняет тайтл в `#det` под ними — «Серии» в плеере
   визуально ничего не делает. Закрывать слои над `det` перед открытием.
2. ТВ выключен / роутер недоступен — `poll` (3476–3519) не трогает `st.media`, таймер продолжает тикать, контролы живые.
3. `start` (3195–3211): ушёл со страницы во время поиска источника → `item?.id != m.id` → Play молча отменён.
4. Плашки `#mpill/#skipb/#fpill` (378–395) выше мини-плеера (~162 px + safe area), а страницы паддят 120 px —
   последний ряд перекрыт.
5. `#toast` (614) при открытом плеере ложится на play/pause и перехватывает тапы — поднять над панелью + `pointer-events:none`.
6. Длинное слово в названии: `#det h1` (213) без `overflow-wrap`, `.hero>div` раздувается, мета обрезается;
   `.work b` (166) налезает на кнопки; `.card b` режется посреди слова.

**Низкие:** `#dacts` переполняется на 320 px; бейджи карточек поиска под кнопкой ✓; ландшафт — нет
`safe-area-inset-left/right`, открытый плеер без max-height; поиск не скроллит в начало, возврат по «Похожее»
сбрасывает scrollTop; `openSeenSheet` при сетевой ошибке пишет «Серий нет»; заголовок person появляется рано
(`offsetTop` против `.pmain`); `#fshot img` без `onerror` — вечный шиммер; `failed()` без повтора и с живыми кнопками;
`duration()` даёт «1 ч 60 мин»; `#tg/#pp` всегда «Пауза» в aria, нет Escape/фокуса в шитах, контраст `#6b6b72`
~3.6:1; hover-стили на iPad без `(hover:hover)`.

**Подозрения:** `api()` без таймаута — зависший `/status` держит `busy` и останавливает поллинг;
нет `overscroll-behavior:contain` на страницах (теперь закрыто фиксом градиента).
