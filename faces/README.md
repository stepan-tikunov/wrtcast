# faces

Находит лица на картинке и считает их векторы, чтобы title-api говорил, кто
из актёров в кадре на паузе (см. «Кто в кадре» в README title-api). Без
состояния: картинка на входе, лица на выходе.

Модели — InsightFace `buffalo_m` (только некоммерческое использование; веса
скачиваются при сборке образа и в репозитории не лежат): SCRFD-2.5G находит
лица и пять точек (глаза, нос, уголки рта), ArcFace R50 (`w600k_r50`)
превращает лицо, выровненное по этим точкам, в 512 чисел; косинус двух
векторов говорит, один ли это человек. Всё на CPU через onnxruntime.

```sh
curl --data-binary @photo.jpg 'http://127.0.0.1:50060/v1/detect?det=640&min=40&max=5'
# {"model":"w600k_r50","width":1280,"height":720,"ms":1160,"faces":[
#   {"box":[x1,y1,x2,y2],"kps":[[x,y],…],"det":0.87,"yaw":0.05,"blur":210.4,
#    "embedding":"<512 float32 LE, base64>"}]}
```

- `det` — до какой стороны картинка уменьшается для детектора (320, 480,
  640, 800; для портрета хватает 320).
- Векторы считаются для `max` самых крупных лиц от `min` px по короткой
  стороне, у остальных `embedding` нет.
- `yaw` — насколько нос смещён от середины между глазами, в межглазных
  расстояниях: около 0 — лицом к камере, больше 0,5 — сильно в сторону.
- `blur` — дисперсия лапласиана выровненного лица 112×112.
- `GET /healthz` — `{"ok":true}`, когда модели загружены.

Переменные: `FACES_ADDR` (по умолчанию `127.0.0.1:50060`), `FACES_THREADS`
(потоки onnxruntime, 2), `FACES_MODELS` (каталог моделей, `/models`).

На старом Xeon сервера (4 vCPU, KVM) SCRFD-10G занимал около секунды на
картинку, SCRFD-2.5G — около 0,15 с; ArcFace R50 — около секунды на лицо при
любом числе потоков (vCPU делятся с соседями). MobileFaceNet (`w600k_mbf`)
был бы в 40 раз быстрее, но хуже узнаёт.

```sh
docker build -t wrtcast/faces:latest . && docker compose up -d
```

Образ собирается прямо на сервере: в контекст уходят только исходники,
а базовый образ и модели сервер скачивает сам.
